# Oukitel: прямий Wi-Fi канал у VOLTOS 2.1

## Чому Cloud оновлюється після відкриття фірмового застосунку

Поточний endpoint `getDeviceBusinessAttributes` читає cloud shadow: останній стан, який станція вже надіслала виробнику. Новий HTTP-запит не є запитом нового фізичного вимірювання. Фірмовий застосунок може встановлювати активну підписку/heartbeat і підтримувати режим звітів — тоді в хмарі знову з’являються дані. Саме таку залежність описав користувач; без доступу до його станції це узгоджена з протоколом причина, а не доведений діагноз конкретної прошивки.

У дослідженому LAN-протоколі P2001E Plus станція потребує регулярного повторення підписки: high-frequency reporting tag 100 = 3, cmd17 read та heartbeat. Відсутність нових пакетів не можна приховати оновленням локального часу.

Джерела: [протокол і дослідження автора](https://github.com/bordeux/ha-oukitel-powerstation), [польові обмеження іншої прошивки](https://github.com/VictorCV-DAM/ha-oukitel/issues/6). Друга публікація описує іншу досліджену P2001 Plus; її обмеження не можна автоматично приписати всім P2001E Plus.

## Як налаштувати

1. Станція вже має бути приєднана до домашньої Wi-Fi мережі. Для первинного provisioning може знадобитися застосунок виробника.
2. Установи VOLTOS 2.1 через Xcode. iPhone і станція мають бути в одній приватній мережі.
3. Пристрої → Oukitel → **Прямий Wi-Fi**.
4. Укажи локальну IPv4 станції зі списку клієнтів роутера. Підтримуються приватні IPv4; порт фіксований — TCP 6607. Масове сканування мережі не виконується.
5. Дозволь доступ **Local Network** у запиті iOS. Якщо відмовив, зміни дозвіл у Settings → Privacy & Security → Local Network → VOLTOS.
6. Якщо Cloud-акаунт уже підключено, VOLTOS запитає персональний ключ **тільки обраної власної станції**. Новий backend endpoint має бути розгорнутий; Xcode sync не публікує сервер. Є запасний ручний ввід власного `authKey` у згорнутому розділі. Не пересилай ключ у чат і не записуй його в Git.
7. За обраної опції ключ збережеться у device-only Keychain. Автопідключення працює після повернення у застосунок; після втрати каналу виконується до трьох повторів із затримкою. Натискання «Від’єднати» вимикає автопідключення.

## Що реалізовано

- Swift `Network.framework` транспорт лише до явно вказаного приватного IPv4, один peer і TCP 6607.
- Обмеження часу підключення, довжини пакетів, session ID; події старого сокета не обробляються новою сесією.
- Hello/nonce → SHA-256 proof → login result = 0. Персональний AES-128 ключ у bundle не вшивається.
- AES-CBC + TTLV, checksum і streaming de-stuffing/fragmentation. Розбираються cmd17 replies і cmd20 reports.
- Повторна підписка й читання кожні 12 секунд; відповідь на ping. Показники доступні як свіжі до 30 секунд від останнього power report. Після 60 секунд без звітів канал скидається.
- Output-only reply не оновлює timestamp старого заряду/потужності. Відсутні або старі окремі поля лишаються невідомими.
- AC/DC/USB потребують підтвердження користувача, відомого свіжого стану й нового пакета з потрібним значенням. ACK сам по собі не є виконанням.
- Історія та CSV розрізняють `oukitel_lan` і `oukitel_cloud_snapshot`.
- Ключ отримується сервером за чинною сесією, після перевірки належності пристрою. Використано поточний vendor `regenerateAuthKey` endpoint, оскільки копія у binding list може бути застарілою. Цей endpoint у дослідженні повертав поточний ключ без порушення роботи фірмового застосунку; vendor-контракт не є гарантованим публічним API.

## Межі перевірки

Новий канал компілюється для iPhone і перевіряється моделлю протоколу з незалежними публічними тест-векторами. Фізична станція користувача не підключалася. Після встановлення потрібно звірити заряд, потужність і команди з дисплеєм конкретного пристрою.

Гарантувати повністю автономну роботу всіх прошивок без vendor cloud не можна: є польові повідомлення про firmware-залежність LAN reports від хмарної сесії. У такому випадку VOLTOS покаже відсутність нових даних. Він не замінює їх часом повторного cloud-запиту.

У LAN-режимі температура не підставляється з давнього cloud shadow: досліджена прошивка не надсилає її локально. Прямий TCP не доступний у Safari/PWA. Закритий iPhone-застосунок не гарантує безперервного моніторингу.
